# Rhythm（作息）

私人作息看板：把「家中设备的只读观察」和「工作机的只读采样」整理成一天的状态时间线、关键时刻和四个数字，并公开每个结论的判断方法与口径。

- `web/` 是 Svelte 看板（今天 / 趋势 / 来源 / 设置）。
- `worker/` 是 Hono Worker，只读两路上游，状态计算是纯函数。
- `migrations/` 是应用自有 D1（SSO 会话表、`settings`、每日汇总 `daily_status` / `daily_metrics` 与重算队列）。
- `shared/fixtures/state-cases.json` 是共享用例，`shared/cases.ts` 负责展开与装载。

## 只读上游

上游通过通用 service binding `STATUS_READ` 访问（`wrangler.toml` 里 `service` 是占位，发布时由 `deploy-domain.mjs --app rhythm` 从本机环境变量 `RHYTHM_STATUS_READ_SERVICE` 注入临时配置，见 [本地发布](../../docs/development/local-release.md#rhythm-首发)）：

| 资源 | 用途 |
|---|---|
| 工作机采样资源 | 工作机每分钟的采样：网络、键鼠空闲、锁屏、应用名 |
| 家中设备资源 | 家中设备的设备表、观察快照、事件与心跳 |

时序资源必须同时带 `from`/`to`（ISO 8601 带时区），跨度 ≤ 8 天，`limit` ≤ 1000，按 `nextCursor` 翻页。上游失败统一返回 `upstream_unavailable`，页面显示「数据暂不可用」，不会用假数据兜底。

## 状态判定

| 状态 | 判断 | 类别 |
|---|---|---|
| 卧室 / 客厅 | 本人手机在线，房间标签对应 | 看到 |
| 在家（房间未知） | 手机在线但房间为空；或工作机网络是 `home` | 看到 |
| 公司 · 在电脑前 | 工作机网络是 `office`，且最近几分钟有键鼠、未锁屏；网络标签上线前，按工作机有操作且手机已知不在家推断 | 看到 / 推断 |
| 公司 · 离座 | 工作机网络是 `office`，但锁屏或没有操作，且夹在两段办公之间 | 推断 |
| 通勤 | 手机最后一次在家 → 工作机第一次在电脑前（下班方向相反） | 推断（上限） |
| 其他网络 | 工作机网络是 `other`，显示网络名，没有则显示网络标识 | 看到 |
| 未知 | 两路都没有新鲜数据，或看不出来 | 无数据 |

手机上线 / 离线事件按时间区间持续到下一条事件或快照；事件中的 `pending-offline`、`no-response` 和空状态维持前一状态，手机休眠不回应扫描期间也延续前一状态；快照中的 `pending-offline` 仍按在线处理并保留 20 分钟 freshness。`no-response` 不单独算在线或离开，没有前态时保持未知，并按快照或事件刷新该设备的观察时间。事件区间超过 36 小时失效。第一条家中心跳之前，按事件区间得出的在家时段标为推断；有心跳时要求最近 20 分钟内存在 `scan_ok=true`，否则为未知。
本人手机有多台设备时，先逐台判断，再合并：任一仍有有效观察的设备在线就在家；没有在线但至少一台有效设备已知离线就不在家；没有任何有效设备就未知。长期没有数据或已超出新鲜度的设备不参与合并，不会阻止其他设备的判断。多台在线优先使用 `seen`，再优先使用有房间的设备，最后按设备 ID 字典序选择证据与房间。

### 阈值

阈值集中在 `worker/state.ts` 的 `STATE_THRESHOLDS`，改阈值必须同时更新 `shared/fixtures/state-cases.json` 与本表：

| 常量 | 默认值 | 含义 |
|---|---|---|
| `activityFreshnessMinutes` | 5 | 工作机采样多久内算新鲜 |
| `homeFreshnessMinutes` | 20 | 家中设备观察多久内算新鲜（要宽过一次扫描间隔） |
| `homeIntervalMaxMinutes` | 2160 | 手机事件区间最长持续 36 小时 |
| `legacyNetworkCutoff` | `2026-11-05T12:12:00+08:00` | 网络标签上线前，满足操作且手机不在家的旧采样可推断公司 |
| `currentStatusLookbackMinutes` | 20 | 当前状态卡回看最近可判断分钟 |
| 来源页家中扫描新鲜度 | 10 | 两次心跳窗口内显示为新鲜 |
| 来源页工作机新鲜度 | 5 | 与 `activityFreshnessMinutes` 一致 |
| `activeIdleSeconds` | 180 | 空闲秒数低于该值算有键鼠活动 |
| `activityLookbackMinutes` | 5 | 「最近几分钟有键鼠」回看多久 |
| `officeAwayMaxMinutes` | 120 | 离座最长多久仍可报告 |
| `commuteMaxMinutes` | 120 | 通勤最长多久仍可报告，超出则保持未知 |
| `wakeEarliestMinute` | 240 | 一天从客厅开始时，最早几点才算「起床」 |
| `futureTimestampToleranceSeconds` | 60 | 上游时间晚于服务器当前时间超过该容差时标记为「时间异常」 |
重算读取家中快照、事件和心跳时回看 `STATE_THRESHOLDS.homeIntervalMaxMinutes=2160` 分钟；工作机采样继续使用原有 30 分钟回看。

时间按 `Asia/Shanghai` 切天；同一时刻写成 `+08:00` 或 `Z` 结果相同。
查看当天时，当前时间之后的分钟标记为「未到」，不参与状态、指标或 App 构成计算；过去日期仍计算完整 24 小时。

### 四个数字

- **上班通勤 / 下班通勤（上限）**：推断区间，缺口超过 `commuteMaxMinutes` 时保持未知，不会硬凑。
- **在电脑前**：时间线里「公司 · 在电脑前」的分钟数。
- **在家**：卧室 + 客厅 + 房间未知。

「在电脑前做什么」按 `net=office` 且有键鼠活动的分钟统计；网络标签上线前推断为 `office_active` 的分钟也计入 App 构成、键鼠和专注。手机落家里时，App 构成仍可能有值，而时间线会显示在家。

## 每日汇总（P5）

- 每天北京时间 04:30（cron `30 20 * * *`，UTC）重算「昨天」及之前 2 天，幂等写入 `daily_status` / `daily_metrics`；迟到的数据靠这 3 天窗口补上。
- 上游按 2 天一段读取（`UPSTREAM_CHUNK_DAYS`），每段按 `nextCursor` 翻页；翻满页数仍有下一页时报 `upstream_unavailable`，不写不完整的汇总。
- 今天永远实时计算、不落库，只出现在逐日列表里（`partial: true`），不进平均、按周对比和异常判断。
- 历史日没有汇总时返回 `missing: true`，所有指标为 null（未知），集合为空。
- 日类型按日历日算：周一到周五为工作日，其余为休息日（节假日留扩展点）。
- Owner 可手动重算：`POST /api/admin/recompute?from=&to=`，跨度 ≤ 31 天且只能到昨天；设置页按 7 天一段依次调用。

### 指标口径

- **专注时段**：连续 ≥ 25 分钟「公司 · 在电脑前」且没切到「沟通」类 App；缺采样的分钟不计入，连续缺超过 2 分钟就结束这一段。
- **在家用工作机（下班后）**：工作日里工作机连着家里网络且有键鼠的分钟，包括上班前在家用的时间；**休息日用工作机**：休息日所有有键鼠的分钟。
- **和平时不一样**：与该日之前近 30 天同类日的平均比，离家 / 开始办公 / 离开电脑 / 到家早或晚 ≥ 阈值分钟，或通勤长 ≥ 阈值百分比；同类日不足 5 天不判断并说明。
- **数据可信度**：有数据的分钟占比，分 ≥ 99% / 95–99% / < 95% 三档；缺口原因分家中扫描没扫到、手机没响应扫描、工作机没上报。

## 趋势与设置页

- 趋势页：近 7 / 30 天切换，8 个模块（各状态时长、作息叠图、通勤与时刻、在公司用电脑、工作节奏、在家、和平时不一样、数据可信度）加本周与上周对比。不足所选天数时按实际天数算并提示；没有汇总的日子画成斜纹「未知」。图表都是手写 SVG，点按或悬停看明细，每个图有一句文字结论。
- 家里暂不区分卧室与客厅，趋势里统一显示「在家」。
- 手机上拆「作息」「工作」两个标签，作息叠图只给文字摘要；电脑上一页展开，顶部锚点跳转。
- 设置页：选择本人手机（候选来自家中设备表，只显示名称、厂商、位置标签）、App 归类、其他网络改名、异常阈值。保存后已汇总的日子标记为需要重算，不自动大批量重算。
- 深色模式跟随系统 `prefers-color-scheme`；共享 token 缺的深色强边界色在 Rhythm 样式里本地补齐。

## 本地检查

```bash
npm test              # 状态用例 + 上游解析 + Worker API + 页面
npm run typecheck
npm run build
npm run test:browser:built   # 合成 SSO + 本地 Worker/D1 + 按日生成的假 STATUS_READ；覆盖今天、来源、趋势、设置，桌面与 390px，浅色与深色
```

浏览器冒烟需要本机 Chrome；缺 Chrome 或端口冲突会直接报错，不会跳过。

## 隐私边界

仓库里不写真实设备名、网络名、房间与地址对应、MAC、IP、私有服务名或用途说明；上游只读接口只用通用 service binding 名 `STATUS_READ`；测试数据全部是合成数据。日志只记录错误码，不记录行数据。
