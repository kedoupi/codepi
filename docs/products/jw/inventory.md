> 缩写：A=`web/src/App.svelte`，W=`web/src/lib/Work.svelte`，T=`web/src/lib/Trends.svelte`，S=`web/src/lib/Settings.svelte`，O=`web/src/lib/RhythmOverlay.svelte`，B=`web/src/lib/BarChart.svelte`，API=`worker/app.ts`，ST=`worker/state.ts`，SET=`worker/settings.ts`，CSS=`web/src/style.css`。

## 概览

- **定位**：私人作息看板。把「家中设备的只读观察」和「工作机的只读采样」整理成一天的状态时间线、关键时刻、四五个数字，并公开每个结论的判断方法（看到 / 推断 / 无数据分开标注）。
- **用户**：仅 Owner 一人（认证后 userId+subject 固定为 Owner，`worker/auth.ts:9-13`）。
- **入口域名**：`jw.codepi.app`（`wrangler.toml` routes，custom_domain）。
- **技术形态**：Svelte 5 单页（Vite 构建到 `dist/`，前端按 `location.pathname` 切页，不是客户端路由，`A:55`）+ Hono Worker（`worker/app.ts`）+ 应用自有 D1（`migrations/0001-0003`）+ service binding `STATUS_READ` 只读上游 + 每日 Cron（北京 04:30，`worker/index.ts:13-20`，重算昨天及前 2 天）。认证走 `@kedoupi/shared/auth/client` 统一登录，会话 7 天（`worker/auth.ts:23`）。无 MCP 工具、无对外公开 API。
- **全局壳**：桌面左侧栏 + 顶栏退出；手机底部 4 项导航，设置从「来源」页右上角入口进（`A:236`、`A:180`、`CSS:79,421-425`）。深色模式跟随系统。

## 对外接口

本应用无 MCP 工具（`services/mcp` 中未发现 rhythm 工具）、无公开 API。以下接口全部需 Owner SSO 会话（401 未登录），写接口还要求同源 `Origin`（API:72-77）。

| 名称 | 用途 | 谁调用 |
|---|---|---|
| `GET /api/health` | 健康检查（SSO 是否就绪，无需登录） | 运维/发布后读回 |
| `GET /api/auth/login`、`/api/auth/callback`、`POST /api/auth/logout` | 统一登录开始/回调/退出 | 登录页、顶栏退出 |

## 日常使用流与体验疑点

使用流（推断）：早上/随时看「今天」当前状态和关键时刻 → 看工作时段与 App → 周回顾翻「趋势」看通勤、几点出门/回来、异常日 → 工作复盘看「工作」专注、被打断 → 数据不对时去「来源」看新鲜度与判断规则 → 在「设置」归类 App、重算历史。

疑点与风险（事实标「事实」，推断标「推断」）：

1. **事实：设置里没有「选择本人手机」**。今天页提示「到设置里选择本人手机」并链到 `/settings`（A:195），但设置页只有 App 归类和网络改名（S:119-178）；接口 `GET /api/settings` 返回 `device_candidates`，`PUT` 支持 `subject_device_ids`（SET:109-114；API:757-781），网页没有界面。未指定手机时，家里部分都是「未知」，用户无路可走。
2. **事实：设置里「近 7 天」时长小字永远不会出现**。前端读 `app_minutes_7d`（S:10,32-38），后端 `publicSettings` 没有该字段（SET:144-155）。
3. **事实：异常阈值不可设，且被忽略**。`/api/anomalies` 固定用 `DEFAULT_ANOMALY_THRESHOLDS`（API:724），不读设置里的 `anomalyThresholds`；网页也没有入口。趋势页文案写「判断门槛固定为 40 分钟 / 50%」，一致但接口有假能力。
4. **事实：登录回跳丢路径**。未登录访问 `/work` 会被 302 到 `/login?return=/work`（API:859），但登录按钮写死 `return=%2F`（A:154），登录后总落到今天页。
5. **事实：日期只能逐日点或改 URL**。今天页无月历、无「回到今天」；工作页完全没有日期选择；离今天很远要多次点击。原型已画月历与「回到今天」，是否要补进代码要决定。
6. **事实：手机端设置入口藏得深**。底部导航 4 项无设置，要先进「来源」再点右上「设置」（A:180,236）。
7. **事实：手机趋势一次只显示一块；「作息叠图」和「在家」手机端完全看不到**（CSS:447）。是有意取舍，改版需保留或明确说明。
8. **推断：「历史日没有 App」被写成提示而不是明显的状态**。今天页对更早日期只显示状态段，具体 App 只在今天和昨天可见（A:216），其余 App 面板会空，用户可能误以为没用电脑。
9. **推断：错误文案过于笼统**。多数失败只显示「数据暂不可用，请稍后重试」，上游失败与未登录之外的原因（如日期无效）也会被折叠。
10. **事实：C-JW 组件稿写「图表用 Chart.js」，代码是手写 SVG（`BarChart/MomentScatter/RhythmOverlay`），且 README 明确「图表都是手写 SVG」**。画板与实现的技术假设不一致，改版前要定谁让步。
11. **事实：设计画布里的 Jw-Today / Jw-Today-Phone 是旧稿**（示例日期、术语和对比文案与现行代码不同），容易误导，改版前建议标过期或删除。
12. **设计要守住的红线（来自 AGENTS.md）**：缺失数据永远显示「未知/暂无」不当 0；通勤、离座、在外、开会必须带「推断」标；页面只按文本节点渲染不用 `{@html}`；移动 390px 不得横向溢出；证据类别（看到/推断/无数据）与「设备在线不等于人在」类提示不能被删。
