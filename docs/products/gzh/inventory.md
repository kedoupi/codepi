# GZH 公众号 功能清单

> 源码根：`~/Coding/codepi/apps/gzh`。`W/` = `web/src/`，`K/` = `worker/`。行号为 2026-11-07 读到的版本。

## 概览

- 一句话定位：微信公众号「珂抖屁」的内部发稿/审稿台。一期只做人审：编辑把某天某档（早/中/晚）的稿件标成待审并附预览，老板手机打开通读后「过 / 要改 / 拒」，过了变「可推箱」，编辑去微信后台人工推草稿箱后再标「已进箱」。不接微信草稿箱 API。
- 用户：张老板（老板，审稿）与编辑（交稿）。生产 SSO 下账号即 owner，同时有编辑与审核权限；多账号 UI 一期不做（`README.md`「产品简介」）。旧的 `gzh-preview` 已并入并下线。
- 入口域名：`gzh.codepi.app`（`wrangler.toml` 注释与 README）。
- 技术形态：Cloudflare Worker（Hono）+ Static Assets（`run_worker_first`，预览正文也先过会话门）+ D1；前端 Svelte 5，三个路径路由（登录 / 看板 / 稿件预览页）+ Shadow DOM 内嵌成稿 H5；手机优先样式（`min-width` 断点 480/640/768）。
- 是否已上线：README 写明「已完成 Worker 与正式域名切换」，`wrangler.toml` 有生产变量与 D1 绑定，推断已上线；「登录后完整稿件流程验收单独记录」，我没有核对该验收是否完成。
- 与外部的接口：对 Desk（project.codepi.app）提供摘要（`K/desk-summary.ts`），无 MCP 工具（grep 未见 MCP 入口，也不在 MCP 工具清单内）。

### 状态机（`K/status.ts`）

draft / 需改 → （交待审）→ 待审 → 过 → 可推箱 → 已进箱；待审 → 要改 / 拒 → 需改；需改、可推箱、已进箱 → 撤回待审。「已进箱」稿不能再改。

## 日常使用流与体验疑点（推断标明）

日常流（推断）：
1. 编辑（目前就是张老板自己或其助手）打开看板，在某天某档点「交本档真稿」填 slug、标题、预览地址、备注 → 标为待审。
2. 老板手机打开看板，看「N 待审」→ 点进稿件，通读 H5 → 过/要改/拒。
3. 过了 → 去微信后台手动推草稿箱 → 回来点「已进箱」。
4. 要改/拒 → 编辑看到「需改」+ 备注，改完再交，或直接撤回待审。

体验疑点：
- **「要改」按钮可点，但后端要求必须有原因**（事实：`desk.ts:528-530`）。而意见框默认折叠在「写意见（可选）」里，界面写的是「可选」。这是 UI 与规则不一致，老板点「要改」不写原因会得到错误提示。
- **待审队列只列「待审」**（事实：`desk.ts:84-91`）。「需改」和「可推箱」没有独立队列，只能到对应日期的三档卡片里找；换天靠前后一天按钮或日期选择器，没有「所有需改/可推箱」的汇总入口。
- **没有档位的稿件只在待审队列里可见**（事实：看板只按 slot 映射三档，`desk.ts:84-91`）；表单也强制选档位，实际应基本不会出现。
- **一天一档只能一篇**（事实：`(publish_date, slot)` 唯一索引，`desk.ts:230`）。多篇同档没法并存，需要确认是否符合真实发稿节奏。
- **交稿表单只有 slug、标题、预览地址、备注，没有摘要字段**（事实：`ComposeForm.svelte`），但 API 支持 `digest`、卡片也显示摘要；摘要来源于何处从前端看不出（推断由别处写入）。
- **预览地址靠手填路径**（事实），封面图靠约定的 `预览目录/cover.png`（`format.ts:44-77`）；填错只会退化成无封面或「没有可内嵌的 preview_path」。
- **拒绝与要改没有区别**（事实：`status.ts`，均进「需改」）；「拒」多了一次确认点击，设计上是防误触。
- **时区**：看板「今天」由前端 `todayShanghai()` 与后端 `shanghaiDate()` 分别计算，页面显示日期取 URL 参数或前端今天（推断存在凌晨边界差异的可能，未验证）。
- 切换日期使用整页刷新（`location.search`），操作后用 `location.reload()`，没有局部更新；手机上有明显闪动（推断）。
- 启动态和错误态较粗：看板整页错误只显示一行文字，没有重试按钮（事实：`Desk.svelte:67-68`），而启动失败（`App.svelte:95`）有「重新连接」。
- 手机优先、大屏只是限宽居中，没有桌面专属布局（`styles.css` 断点只有 `min-width`）。
- 预览内嵌用 Shadow DOM，样式依赖预览 HTML 里引入的样式表；改版需保持清洗规则（去脚本、iframe 等），否则安全边界会变。
