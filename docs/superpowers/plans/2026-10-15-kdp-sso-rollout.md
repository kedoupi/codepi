# KDP 统一登录：验证与发布

## 目标与边界

GU、Oura、发稿台共用一个本人账号。验证码只发送到服务端配置的固定邮箱，
不开放注册，不允许通过请求参数指定收件人。中心身份为 `kdp-owner`，各站点
继续使用已有的数据身份，不迁移健康记录、投资数据或发稿账号。

网站会话与 Oura 数据授权相互独立。网站退出撤销当前浏览器的中心会话，
使三个站点的对应本地会话失效；不删除 Oura token、不取消定时同步，
也不撤销已经授予 MCP 客户端的授权。其他浏览器的中心会话不受影响。

协议与接口以 [SSO 契约](2026-10-15-kdp-sso-contract.md) 为准。

## 用户流程

1. 从任一站点选择登录，跳转到 `auth.kdp.cool`。
2. 中心会话仍然有效时直接返回原站点；否则向固定邮箱发送验证码。
3. 验证码校验后，中心签发一次性授权码；站点通过服务绑定和 PKCE 交换会话。
4. Oura 首次进入后单独连接 Oura；断连时仍能进入网站、查看已存档数据和设置。
5. 在任一站点退出后，其他站点下一次 API 请求即拒绝该会话。已打开页面通过
   30 秒轮询或窗口重新获得焦点时的检查清除私人内容。后台标签页的计时器
   可能被浏览器节流，不能承诺退出后所有标签页恰好在 30 秒内更新。

中心会话最长 30 天；Oura 本地会话最长 30 天，GU / 发稿台最长 7 天，
均不能超过中心会话到期时间。7 天后可通过仍有效的中心会话重新进入，
不需要因此重复收验证码。

## 发布前置检查

- 确认 GU 生产来源：当前仓库说明为 `kdp-gu.pages.dev`；`gu.kdp.cool`
  只有在域名实际绑定并验证后才能作为入口。中心允许的回调必须逐项精确登记，
  不使用通配符，不从浏览器参数动态扩大名单。
- `kdp-auth` 使用独立 D1 数据库。业务站点新增 `kdp_sso_*` 表，
  不删除或改名既有业务表。
- 服务端 secrets：固定 `OWNER_EMAIL`、发信凭证、OTP 和会话密钥，以及
  中心的 `SSO_CLIENTS`。三个客户端分别使用不同的 `AUTH_CLIENT_SECRET`。
  不把凭证、完整邮箱、验证码写入前端、日志或仓库。
- Oura 的 `PERSONAL_OWNER_ID` 必须指向已有真实用户；不得新建一个空用户
  来代替原有健康数据所有者，也不得使用开发用户。
- 各客户端的 `AUTH` 服务绑定指向 `kdp-auth`。生产与预览配置要分别检查；
  不将任意预览域名加入生产回调名单。
- 初始发布保留 `SSO_ENABLED=0`；开关为 `1` 但配置缺失时必须拒绝访问，
  不自动降级到旧登录机制。

## 发布顺序

1. 创建中心 D1，配置中心域名和 secrets，应用中心迁移并部署 `kdp-auth`。
2. 验证中心健康接口；通过真实域名验证 HTTPS、Cookie 与固定回调。
3. 在三个客户端应用新增迁移，配置各自 secrets 和 `AUTH` 服务绑定。
4. 发布客户端，先保持 `SSO_ENABLED=0`，确认已有功能仍正常。
5. 先为一个客户端启用 SSO，验证固定邮箱收信、回调、已有数据访问及退出。
6. 依次启用另外两个客户端，验证跨站免重复验证码和统一退出。
7. 验证 Oura 授权失效时网站保持登录、历史数据仍可读、重新连接恢复同步，
   且网站退出后后台同步与已有 MCP 授权仍独立工作。

必须先验证中心可用，再启用客户端。不要在一次未经验证的部署中同时切换
三个生产站点。需要用户输入的生产验证码由用户填写，不记录或持久化。

## 自动化验收

- 共享客户端：事务绑定、PKCE、并发回调只能成功一次、非法回跳、中心会话
  撤销与基础设施故障的区分、本地有效期限制、跨来源退出拒绝。
- 中心认证：固定收件人、OTP 有效期与发送限额、错误次数限制、验证码重放、
  授权码重放、客户端凭证、精确回调、跨客户端会话隔离和统一注销。
- 业务适配：启用 SSO 后旧登录不能绕过；既有业务身份不变；服务故障返回
  可重试错误而非伪装成账号过期；退出后的迟到请求不能重新显示私人内容。
- Oura：网站会话与数据授权独立、授权回调绑定发起会话、MCP 和定时同步回归。
- 构建：中心、GU、发稿台、Oura 的测试、类型检查和构建分别通过；
  公共库变更触发业务站点 CI。

本地测试不能证明生产邮件到达率、DNS、实际 secret 配对或服务绑定正确。
这些项目必须在生产切换时单独验收。

## 故障恢复

中心暂时不可用时，受保护操作返回可重试错误，不能创建未验证会话或把所有
用户误判为已经退出。恢复中心或回滚到上一已验证的 SSO 版本优先于关闭 SSO。

`SSO_ENABLED=0` 会重新启用旧认证路径，旧的未过期会话可能重新生效，因此
它是发布阶段的兼容开关，不是无条件安全的紧急回滚按钮。若切换后必须回退，
应先评估并撤销旧会话，保留新增表和已有健康数据，不回退或删除业务数据。
