## 3. 第一批：恢复可靠访问、隐私和会话体验

### A1. 修复自定义域名（F1）

- 重新读取 Pages 域名状态、现有 DNS 和证书状态，确认仍是同一问题。
- 记录 `gu.kdp.cool` 的变更前配置，只修复这个主机名指向 `kdp-gu.pages.dev` 的必要记录，不修改通配符或其他子域名。
- 等待 Pages 域名验证及 HTTPS 就绪，验证静态资源、登录入口、鉴权 API 和固定邮箱登录。
- 保留 Pages 地址作为兼容入口；先不强制全站跳转。自定义域名与 Pages 域名的会话不共享，首次访问新域名需重新登录。

验收：自定义域名可用、证书有效、未登录私有 API 返回 401、登录后能读取正确生产批次；邮件发送及新域名 Cookie 单独验证。若外部验证尚未完成，明确标记等待项，不影响本地其他修复。

### A2. 完整的隐私显示模式（F2）

- 统一金额卡、持仓明细、报告摘要/标题、自由文本告警和数据提示的隐藏策略。
- 不依靠简单数字正则猜测哪些文字是账户金额。隐藏模式对可能含私人金额的报告摘要和自由文本采用安全摘要或占位说明。
- 风控动作不能随金额一起消失：仍展示“停买”“暂停月投”“48 小时冷静期”等结构化动作及必要比例/期限。
- 保留当前筛选、历史日期和路由，切换隐藏模式不重置用户阅读位置。

主要文件：`gu/web/src/main.ts`、`risk-summary.ts`、相关前端测试。

验收：含金额的总览、列表、正文、提醒测试样本均不遗漏；切换页面、刷新和失败状态仍尊重隐藏设置；规则动作保持可读。

### A3. 认证、数据和错误状态分离（F4）

- 分别记录认证状态与数据状态：未知/已登录/未登录；加载中/就绪/空批次/失败。
- 只有明确 401 或成功退出才进入未登录状态；有效会话下的空批次与服务故障不误跳登录。
- 缓存数据可在网络失败时继续展示，但错误与原批次时间应随页面切换保留，直到成功刷新或重新登录。
- 登录恢复原本的合法站内路由；不接受外站跳转地址。
- 保留已有并发请求隔离，避免过期、退出或后发请求被旧响应覆盖。
- 刷新按钮显示进行中并避免重复请求，结果区分新批次、没有新批次与失败。

主要文件：`gu/web/src/main.ts`、`gu/web/test/session.test.ts`。

验收：覆盖 401、404、500、非 JSON 错误、断网、慢请求、并发刷新、退出、深链接登录恢复；空态和错误态的导航、重试均可用。

## 4. 第二批：数据语义和日常阅读

### B1. 行情时间与刷新反馈（F3）

- 明确按钮含义为“刷新已同步数据”；它不隐式触发券商操作或实时行情采集。
- 将来源提供的行情时间作为带时区时间戳传递到可选字段；保持数据生成时间、网站接收时间、账户确认时间各自独立。
- 只在有明确来源证据时标识盘中/收盘状态；旧批次或证据不足时显示“未记录/未确认”，不能通过日期猜测。
- 总览显示批次更新时间与经过时长。没有可靠交易日历前，不把周末或休市期间简单判为漏更。
- 历史报告明确标注适用交易日和“当时结论”，不与当前规则状态混在同一行动结论中。

主要文件：投资工作区 `scripts/quotes.py`、`build_dashboard.py`、相关 Python 测试；`gu/worker/data.ts`、`web/src/main.ts`、前端类型与测试。

验收：新旧批次均可读；缺失时间不伪造；跨时区、旧批次、混合行情日期、网络失败都有清楚文案；刷新前后批次变化可辨识。

### B2. 百分比和最低线口径（F6）

- 保持风控计算用原始精度。检查数据传输中的提前取整，统一前端的显示精度与舍入规则。
- 同一指标的表格、图表、详情使用相同的显示口径，旧字段作为兼容回退。
- 所有现金配置位置统一写“最低保留线”，保留股票的“目标权重”语义。
- 用已有 `cash_after_dca` 展示本次月投后的估算现金缓冲，显示计算依据及账户数据日期；不把估算结果表达为下单许可。

验收：覆盖 XLV 已发现样本及临界舍入样本；相等阈值的比较结果不变；隐藏模式不暴露账户金额；不重算或补写真实持仓。

### B3. 总览优先呈现需处理事项（F5）

建议内容顺序：

1. 账户/行情时间与数据提醒。
2. 当前触发动作、临近分析要求、月投现金约束。
3. 估算资产与配置缺口。
4. 最近报告，明确历史日期。
5. 持仓变化与市场概览。

- 合并同一规则的重复提醒，保留严重程度、动作与期限；GOOGL 高阈值优先级继续保留。
- 没有触发首次时间或交易日历时，只展示规范要求，不虚构决策截止日期或完成状态。
- 持仓历史仍明确是权重记录，不改变为收益曲线。

验收：手机无需翻过长图表就能看到需要处理的规则；无告警、停买、强制减仓、疲劳锁和多项告警都有清楚的展示。

### B4. 手机持仓与报告阅读（F5）

- 桌面保留比较表格。手机优先使用紧凑持仓卡片：标的、市值、浮盈亏、当前权重及目标/最低线；股数、成本与行情时间放展开详情。
- 手机历史图继续支持横向探索，并提供日期选择和数值替代；不通过缩小字号硬塞所有内容。
- 报告列表使用简短标题、日期和有限行数摘要；长历史分类映射为展示分类，保留原类型供追溯。
- 长报告增加章节目录和返回顶部，修正有序列表与主标题语义。
- 切换路由后的焦点、键盘访问、移动端触控目标和减少动态效果一起验收。

主要文件：`gu/web/src/main.ts`、`charts.ts`、`markdown.ts`、`style.css`。

验收：320px、390px、768px 和桌面；长中文名称、长报告、无报告、无匹配结果、历史数据缺失；筛选和选择在阅读返回后保留。对确需横向滚动的图表给出提示，不允许整页溢出。
