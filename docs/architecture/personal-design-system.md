# kedoupi（codepi）个人站设计规范

**品牌、token、组件、可访问性和各应用主题边界统一见
[CodePi Design System 规范](codepi-design-system.md)。** 本文只保留主站布局、
公开页与应用边界等个人站约束；两者冲突时以 CodePi Design System 规范为准。

适用范围：`packages/shared/products.ts` 登记的全部产品，以及 Auth/MCP 的登录与授权页面。
具体页面改动仍需桌面/手机验收，不能仅凭导入 token 判断完成。

## 设计原则

- 以个人介绍、实际内容和工作任务组织布局。
- 主站提供舒展的阅读节奏；工作应用保留合适的信息密度。
- 同一品牌共享配色、字体、间距、圆角、组件风格、图标规范和交互语义；各 app 只补充本应用的语义色，不另立品牌色，也不要求所有页面使用同一种布局。
- 没有真实内容时省略模块或说明当前状态，不编造文章、指标或个人经历。

## 主站布局

- 品牌版官网按「一屏讲一件事」组织内容：首屏价值主张、生活数据与 AI 的关系、生活连续性、授权边界、公开内容与收尾。
- 关于页只讲个人数字空间的理念、三段双色宣言和公开/私域边界，不展示三条生活脉络、产品清单或项目介绍。
- 桌面页面使用舒展的单列阅读宽度与深色整屏边界区；手机保持单列阅读，区块上下留白缩小，公开/私域两列改为单列。
- 顶栏主导航固定为四项：`首页`、`博客`、`关于`、`隐私说明`；右侧保留「我的工作台」文字链接，手机收进菜单抽屉。
- 页脚包含符号、`BUILD · THINK · CREATE`、四项主导航和「我的工作台」，版权为 `© 2026 kedoupi（codepi）`。
- `/desk/` 只生成无私人数据的页面壳；应用数据由已鉴权的 `/api/*` 返回。公开首页与品牌页不请求私人应用数据。
- 博客与文章页保留公开内容阅读、RSS、分类、标签、系列和审核预览能力；旧应用目录、联系页、使用说明页和 Three.js 原型已退役。
- 首页与使用 `BaseLayout` 的公开页共用品牌版页头、页脚、容器尺寸和交互，不另设首页专属页头变体。
- 未发布栏目不加入导航；建设状态不做成可点击的假按钮。
- 公开页不请求私人应用数据；外链在新标签页打开时使用明确的辅助说明。

## 应用边界

- 产品名称、公开用途、访问方式和当前入口集中在 `packages/shared/products.ts`；域名映射见根 README。
- Health 应用使用本地暖色主题；MCP 授权页和统一登录页直接嵌入共享 tokens.css，其配色独立管理。旧 Oura/工具站域名不保留兼容。
- 公众号稿件台 gzh 已于 2026-11-08 退役，数据按所有者决定删除。
- GU 使用自己的 Svelte 应用样式，从 `apps/gu/web/src/style.css` 引入共享 tokens，保留各自信息密度与业务主题。
- Health 的登录入口、导航、概览和详情页沿用共享组件风格，保留自身配色和当前布局。私人应用的 UI 变更仍须检查桌面、手机、登录、空状态、错误状态及图表。
- 不能以“已经有 token 文件”宣称所有私人应用已完成视觉统一。

## 去广告

共享广告 loader、广告组件与占位、`ads.txt` 已移除，旧工具站和工具 URL 已退役，
不恢复入口、广告或兼容页。历史实施顺序保存在任务记录中。

不再以 AdSense 复审作为页面结构或内容调整的约束。历史复审文件作为历史资料保留。
