# kedoupi（codepi）共享设计规范

状态：P1 主站已采用；私人应用在后续迁移阶段逐项接入。

## 设计原则

- 以个人介绍、实际内容和工作任务组织布局。
- 主站提供舒展的阅读节奏；工作应用保留合适的信息密度。
- 同一品牌共享颜色、字体、间距、圆角、图标和交互语义，不要求所有页面使用同一种布局。
- 没有真实内容时省略模块或说明当前状态，不编造文章、指标或个人经历。

## 唯一视觉来源

`shared/styles/tokens.css` 定义品牌 tokens，`shared/styles/site.css` 定义静态站点通用外观。六个静态站通过 `BaseLayout.astro` 使用同一套样式。

私人应用接入时导入 token 文件，将已有语义变量映射到共享 token，逐项消除硬编码品牌色；不只在文件末尾覆盖颜色。图表的盈亏、警告和数据系列色仍保持清楚且独立的语义。

| 项目 | 规则 |
| --- | --- |
| 背景 | `--kdp-canvas`，浅灰蓝；页面首部只用轻微环境渐变 |
| 内容面 | `--kdp-surface`，白色 |
| 正文与标题 | `--kdp-text` / `--kdp-ink` |
| 次要信息 | `--kdp-muted`；不能用于不可辨认的低对比度文本 |
| 主要动作与链接 | `--kdp-accent`；悬停使用 `--kdp-accent-strong` |
| 字体 | Avenir Next + PingFang SC / Hiragino Sans GB / Microsoft YaHei；不依赖远程字体加载 |
| 间距 | 4、8、12、16、24、32、48、64px |
| 圆角 | 控件 8px；局部内容 14px；主要内容面 20px |
| 阴影 | 仅用于内容面层级，低强度，不使用通篇重阴影 |
| 图标 | 24px 基准，1.7px 线宽，统一圆形端点；颜色继承 `currentColor` |
| 页面宽度 | 内容最大 1120px；连续阅读最大 720px |
| 点击区域 | 主要控件至少 44px 高 |
| 动效 | 160ms，服务交互反馈；尊重 reduced-motion |

## 主站布局

- 桌面：左右个人介绍与应用关系图；横向应用列表；下部内容积累与 AI 连接。
- 手机：单列阅读，应用关系图保留可点击入口；应用列表缩小图标，保持文字完整。
- 首页、应用、关于、联系、隐私和工具存档共用导航、页脚及内容排版。
- 未发布栏目不加入导航；建设状态不做成可点击的假按钮。
- 公开页不请求私人应用数据；外链在新标签页打开时使用明确的辅助说明。

## 应用边界

- 产品名称、公开用途、访问方式和当前入口集中在 `shared/products.ts`。
- Health 展示新名称，但在 P2 验证完成前继续链接原 Oura 域名。
- GU 保留现有域名；公众号工作台不提前启用候选域名。
- 私人应用本轮没有全面换肤。后续 Health、GU、公众号每次迁移时须同时检查桌面、手机、登录、空状态、错误状态及图表。
- 不能以“已经有 token 文件”宣称所有私人应用已完成视觉统一。
