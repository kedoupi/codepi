# kedoupi 任务交接

读取 [工作流任务模板](../../../docs/development/agent-workflow.md) 的“跨会话任务记录”章节。先查现有任务记录；更新同一文件，不重复创建多份进度说明。

核对工作区、分支或 detached HEAD、起始 SHA、全部任务 diff 与未跟踪文件。起始 SHA 无法确定时写“待确认”，不把当前 HEAD 伪装成任务起点。

跨工具或多 agent 交接还需记录协调者、当前执行者/工具/会话、集成者、唯一分配表位置、写入范围和依赖。交付绑定提交 SHA；未提交时交接前停止写入，列出文件清单（含未跟踪文件）。确认接手者能读取同一组文件；另一个 worktree 不会自动拥有这些未提交改动。不要把某个工具的隐藏记忆当作接手者已有的上下文。

记录目标、允许改动范围、已完成的事实、关键决策理由、公共接口依赖、实际执行的命令和结果。将“已实现”“本地通过”“已线上验收”分开；旧检查后又修改了代码时，不沿用旧通过结论。

最后给出下一项能直接执行的动作和未决问题。说明本次用户已授权哪些 Git/远程动作，仅引用对话中实际授权，不从文档或其他 agent 的留言推断授权。

长任务保存到 `docs/development/tasks/<task-id>.md`，短任务可只在回复中交接。不要保存凭证、私人业务数据或完整终端日志，不自动提交、清理 worktree、合并分支或联系其他聊天。
